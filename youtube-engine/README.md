# Shared native YouTube engine — foundation

Independent Kotlin/Android modules: API, core, and a small transport probe app. Baseline: compile/target 36, min 26. No Veya, Annie, or Lyra integration here.

The probe app searches, resolves a video, reads actual bytes from one video and one audio representation where available, and refreshes a format by stable itag. A format URL alone is **not** transport proof. Failure and challenge cases must be reported explicitly.

## Current limitations

- `SessionProvider` supplies request headers scoped to each URL and receives response `Set-Cookie` values so the host can persist them in its own origin-aware cookie store. The engine installs no process-wide cookie handler. Session-assisted request headers are additionally restricted by the engine to HTTPS YouTube origins, and host headers cannot override engine-owned User-Agent, client-version, content, range, or visitor-data fields. Innertube retries rotate through the configured client strategies. HTTP 400/403 invalidates the bootstrap and forces a fresh web key/client version before the next strategy attempt. Search uses bounded client fallback for empty renderer responses; details can fall back to the watch-page player response when Innertube is challenged. Direct URL formats only. DASH-manifest-only, ciphered, untransformed n-parameter, SABR and challenge cases are identified separately when encountered. Cipher metadata is parsed into validated HTTPS URL, encrypted `s`, bounded `sp`, and embedded `n` components; malformed cipher metadata is classified separately rather than treated as a valid cipher challenge. The core exposes bounded signature-decipher and n-transform hooks keyed to the player JavaScript URL. A ciphered format is admitted only after the signature hook returns a changed token and the engine safely writes that token into the declared `sp` query parameter; otherwise it remains excluded and classified as CIPHERED when no usable formats remain. Untransformed n URLs remain marked on each format; a future-valid CDN 403 is classified as N_PARAMETER_REQUIRED instead of being mislabeled expired. Bootstrap discovers the current WEB player-script identity and player-response assets can override it. That bootstrap script is never reused for non-WEB clients unless their response advertises the same script itself. A player-script change invalidates both transform caches. Transform-provider exceptions are contained without swallowing coroutine cancellation. No arbitrary player JavaScript is executed and no transform is claimed unless a transformer returns a changed token.
- Search continuation, subtitle retrieval, and timestamp chapters are covered by live CI checks. Channel pages, playlist paging, comments/replies and broader search renderer variants still need implementation and tests.
- The API refreshes an expired signed URL by a client-independent v2 track identity (itag, media kind, container, codecs and available video/audio characteristics) and retries the same byte range. Subtitle tracks have their own stable identity and can be reloaded through video details after URL expiry.
- Chunk reads return actual bytes and a transfer checkpoint for the host app to persist. The engine has a checkpoint-native resume path that refreshes the stable format, compares the checkpoint's expected total length with refreshed descriptor metadata and the resumed CDN Content-Range total, and refuses the resume with CONTENT_LENGTH_CHANGED (or UNSUPPORTED when the server omits required length evidence) rather than risking partial-file corruption. Media reads use a bounded three-attempt retry budget only for transient I/O/408/425/5xx/short-body failures; 429, expiry, transform requirements and integrity failures are never blindly retried. Redirects are followed explicitly for at most five hops and only to HTTPS URLs without user-info, with Range and engine-owned headers reapplied on every hop. Live CI recreates the engine object and resumes at the saved offset through the checkpoint path, then proves two consecutive 1 MiB ranges; durable checkpoint storage remains the consuming host's responsibility.
- No third-party extractor code has been copied. Only original code is in these modules; no external extractor license obligations have been introduced.

CI runs network instrumentation tests on an API 36 emulator. They must search and page results, load video details, retrieve a refreshed live caption, classify challenged chapter metadata accurately and validate ordered timestamp chapters deterministically, resolve a compatible 1080p+ adaptive video/audio pair, read at least 512 non-HTML bytes from both CDN URLs, resume a nonzero byte range, refresh an expired descriptor by stable identity, and resume again after recreating the engine instance across consecutive 1 MiB ranges. The tests fail if any stage fails. Deterministic tests cover `SUPPORTED_AND_PROVEN`, `CHALLENGED`, `CIPHERED`, `N_PARAMETER_REQUIRED`, `SABR_ONLY`, `DASH_MANIFEST_ONLY`, `EXPIRED`, `RATE_LIMITED`, `TRANSIENT_NETWORK`, `REDIRECT_FAILED`, `CONTENT_LENGTH_CHANGED`, `MALFORMED_RESPONSE`, and `UNSUPPORTED` classification, plus bounded signature/n query rewriting and player-script cache invalidation. GitHub Actions also builds an ARM64 probe APK for Galaxy A16.

`resolve()` returns unverified descriptors. `resolveVerified()` performs both CDN byte probes and is the only operation that returns `SUPPORTED_AND_PROVEN`. No client response with only SABR metadata or ciphered formats is reported as playable. Alternate client identities are bounded to four attempts; the current web key/version is rediscovered after 15 minutes or an HTTP 400/403.
