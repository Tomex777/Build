PDMX LARGE-LIBRARY CORRECTION
- PDMX's `tracks` column contains zero-based General MIDI program numbers joined with '-'; it does NOT contain words such as 'piano'.
- The builder parses programs correctly. Piano family = GM programs 0..7 in PDMX/MusPy's zero-based representation.
- Default strict policy requires all declared programs to be piano programs. `--allow-mixed-piano` relaxes this to any piano-containing score.
- `--offset` + `--limit` provide deterministic sharding (max 5,000 songs per pack).
- Optional `--min-notes` / `--max-notes` can create beginner-focused subsets.
- Exact third-party corpus files are NOT embedded in this source archive.

SOURCE RESEARCH POLICY
- PDMX v9 is the primary large public-domain MusicXML source. Its maintainers report 31,221 license conflicts and recommend the 222,856-score `no_license_conflict` subset.
- Slumber further requires all-valid, deduplicated, explicit public-domain/CC0 metadata and conservative piano-program filtering.
- OpenScore Lieder is CC0 and useful as a future secondary corpus, but voice+piano scores need deliberate piano-part selection.
- Mutopia is useful but licenses are piece-specific and must be preserved per score.
- MuseTrainer is a useful public-domain MusicXML reference for familiar titles, but Slumber does not blindly copy arrangements without a clear file-level license trail.
- Piano-Tiles-style games use structured note charts in multiple formats; Piano Tiles 2 community tooling includes MIDI-to-JSON. Slumber uses standard MusicXML/MXL + MIDI and does not copy proprietary Piano Tiles song assets.
