# NIGHT Play / Jigsaw co-op — Agent 8 integration contract

**Status:** Authoritative, independently testable state reducer only. Not a finished or deployed online co-op game. This module does **not** permit calling Jigsaw "online" in the catalogue. It makes no MSCC production modifications.

`co-op-state.cjs` is a dependency-free Node 22 CommonJS state engine, to be invoked exclusively by authenticated MSCC backend RPC handlers. It accepts trusted, server-resolved `actor` IDs: NEVER use an `actor` or player name from the browser as proof of identity.

1. Create `createPuzzle({photoId,count,hostId,hostName,seed})` server-side. Valid counts: 24 (4×6), 48 (6×8), 144 (12×12). Restrict `photoId` to a real approved gallery ID and prevent arbitrary remote URLs. Image source/gallery selection belongs to the host.
2. Persist **the full private state** (players, leases, opLog, piece groups, revisions) with TTL and room ownership in server storage. Apply `applyCommand(state,command,now)` in a **SQLite transaction protected by revision compare-and-swap** or serialize writes with a DB write lock. Two Node processes reading the same revision must not both succeed. Persist result only when `accepted` and revision changed.
3. Resolve actor from HttpOnly verified WhatsApp session or server-issued scoped guest cookie. `join` accepts a server-sanitized guest name; `rename` MUST take the authoritative current profile name, not arbitrary client-editable value for linked users. Max 16 players. `publicSnapshot(state,viewer,now)` strips all IDs, session values, lease owners and idempotency history before sending state to guests.
4. Piece events: `claim` with `pieceId,expectedVersion`, drag locally under the finger, `renew` a held lease every few seconds during long drags, then `drop` with `pieceId,expectedVersion,x,y,mutationId` (client-generated collision-resistant ID) or `release` on cancellation. Coordinates are **puzzle cell units**, not viewport pixels: `x=col,y=row` is the authoritative board position. The server handles adjacent-group merging, board snapping, counters and completion. Do not stream every pointermove to the backend or redraw 144 pieces for every movement. Authoritative post-drop snapshot reconciles remote views.
5. Reject stale locks, stale per-piece versions, unauthorized actors, malformed positions and replayed commits. Retry uncertain `drop` with the **same mutationId**, never a new one; opLog is capped at 96 recent entries. Lease is 12 seconds and requires renewal for longer drags.
6. A5-owned `PuzzleBoard` uses serialized `nx,ny` viewport ratios, which are **not suitable as network authority across phone vs desktop**. A5/A8 must agree an adapter converting canvas (`boardX,boardY,pieceWidth,pieceHeight`) to and from canonical cell-unit positions, and ensure moving groups preserve relative offsets. In particular, online board construction must use server seed/state, not each client's independent `Math.random()` scattering or randomly generated edge shapes. Coordinate screenshot testing must cover 320,360,390,412,1280 and portrait/landscape.
7. The signed API gateway `night-play/api/account.js` currently has no co-op actions, and MSCC protected PR #387 handles *party* rather than Jigsaw. Do NOT add a browser-only mock backend or deploy protected MSCC without explicit approval. Integrate gateway + transaction-backed backend and run **host plus two independent physical/remote clients** with real persistent sessions before marking co-op RELEASED.

Run: `node night-play/multiplayer/jigsaw/co-op-state.test.cjs`. Automated reducer assertions are useful but are **not** a real cross-device browser playtest or live server QA.
