# NIGHT Channels — Agent B: curation & news

**Scope:** independent, backend-side content discovery and ranking. No website shell, account router, Azure worker, media compositor or publishing operation is changed by this module. It belongs to the one NIGHT Play combined-preview integration line; its presence on a PR is **not** evidence that any feature is deployed.

## Integration contract (A and C)

**A's current preview object compatibility:** `toReviewCard(normalizedMeme,{previewUrl|previewData})` in `contracts.cjs` maps nested B `media/source` data into A's flat `{id,caption,category,title,sourceName,sourceUrl,previewUrl|previewData,publishable,reviewOnly,publishBlockedReason,rightsStatus,sourceRights}` shape. **Cross-agent enum:** A's approval gate specifically requires `rightsStatus:'verified'`; B's internal `source.rights:'cleared'` maps to that value. Unclear media maps to `rightsStatus:'unverified'`, `publishable:false`, `reviewOnly:true`; `sourceRights` retains the internal source-rights classification. This is preview authorization metadata only, not final publishing permission. The proxy preview must be **same-origin and server-authorized**; raw Reddit/media URLs are not embedded as images in A. Display rights-blocked cards only as discovery if source conditions allow, with disabled Approve/Publish until C records actual redistribution clearance. Never mistake a signed preview URL for permission to repost.

`core.cjs` exports `normalizeMeme`, `memeScore`, `chooseFourMemes`, `normalizeNews`, `chooseNews`, and de-duplication utilities. `sources.cjs` exports `redditAdapter`, `rssNewsAdapter`, `licensedCatalogAdapter`, `boundedGet` and `SourceError`. Runtime: Node >=18; no extra dependencies or credentials committed.

**Atomic four-card bridge:** Backend integration may pass exactly four distinct normalized meme candidates plus a server-created per-ID preview map into `toReviewBatch(items, previewsById)`. It rejects 1–3 candidates, repeated IDs and missing/unsafe previews **before** forming a UI batch, instead of sending a malformed response that A rejects after replacing review state. It does **not** allocate `batchId` or persist approvals; those must come from C's authenticated owner+channel transactional review store. `find` and `next` must never overwrite already approved items; preserve the cross-batch selection tray on the server. If not enough authorized candidates exist, return a visible shortfall/error rather than fabricating four.

**Meme candidate:** `{id,kind:'meme',category,caption,createdAt,media:{url,mime,width,height,byteLength,perceptualHash},source:{id,provider,url,externalId,author,attributionRequired,rights,license},metrics,score?,publishable}`. Four selection cards are returned from `chooseFourMemes(items,{enabled,categories,allowDark,used,feedback,now})`; this returns an empty list when `enabled` is not explicitly true. Persist `used` per owner/channel/session (IDs *and*, where available, earlier candidate objects for near-duplicate protection). All candidate IDs are source-scoped deterministic SHA256 digests. Caution: a new `score` is an advisory ranking, **not** posting permission.

**Actual review learning:** C can pass the durable **per-owner/per-channel** history of `{category,decision:'approved'|'declined'}` into `deriveHumanFeedback(history)` and use its result as `chooseFourMemes(...,{feedback})`. The category weights use a smoothed neutral prior; skipped items are not treated as failures; history is bounded to 5,000 events. The optional persisted `{sourceId}` field adds a **per-source/subreddit** smooth preference, bounded to 256 distinct sources; it contributes 30% of the feedback component and leaves 70% with category preference. Source feedback only changes ranking, never licenses media or auto-publishes it. Source IDs and human decisions must come from server-validated review events tied to the authenticated owner+channel, not a browser-supplied training history. Do **not** merge feedback across unrelated owners, publish reviews, or imply a paid AI model is doing this ranking. More detailed content-aware ranking and validated historical replay is an integration task; this feedback supports honest deterministic improvement.\n\n**Source rights:** `redditAdapter` needs a valid pre-authorized OAuth token provider, an explicitly allowed subreddit list, an **explicitly configured real registered Reddit User-Agent** in `platform:app:version (by /u/operator)` form, and a **required** shared app-wide quota-claim callback (durably coordinated across worker instances) managed by integration. No fictional default operator identity is provided. This follows Reddit's current official API support guidance (https://support.reddithelp.com/hc/en-us/articles/16160319875092-Reddit-Data-API-Wiki); registration, access approval, and terms review remain operational release gates. It uses `top?t=all` so older jokes stay eligible, bounded HTTPS responses, no redirect following, pagination tokens, local throttle and Retry-After. It **always labels Reddit media rights `unknown` and `publishable:false`**, even when source posts are publicly readable. Discovery/preview does not grant republication rights. C must require a rights-approved asset/permission record and verify every posting condition again; A should show a clear rights requirement rather than a fake Publish-ready card. Provider terms, API access, caches and licences require a legal/integration review. No unauthorized scraping fallback.

**Rights-cleared media alternative:** `licensedCatalogAdapter({id,loadRecords,verifyRights})` discovers only media for which the server-managed rights catalogue returns a verified asset + license-evidence pair. The verifier must consult trusted records, never browser-supplied flags. Missing evidence and failed checks are rejected. This makes a legal path for owner/creator-submitted, approved media independently of Reddit source rights. C must **reverify rights at send time**, not trust an old candidate's `publishable` field.\n\n**News candidate:** `{id,kind:'news',title,summary,publishedAt,show,tags,verification,requiresReview,fingerprint,source:{id,name,url,provider,attributionRequired},autoEligible}`. `normalizeNews` only accepts fresh, trusted **exact-host** links; by default, only last 14 days. A vetted per-feed `interpreter(row)` provides show, event, tags and confirmation metadata; an item is `official` and `autoEligible` **only** when the source is marked an official channel and the record has confirmed metadata, with rumor taking priority over that status. Anything else requires owner review. Summaries are original short metadata templates, not copied article text. Do not claim all nuance is fact-checked automatically. To consolidate differently worded stories across outlets, the source-specific interpreter should set identical verified `storyKey` values such as `aurora:renewal:2026`; absent a key, the engine uses a conservative normalized title+show+event fingerprint.

**Review vs automatic feed selection (follow-up):** `chooseNews(items,{enabled:true,mode:'review'|'automatic',...})` defaults to **review**. `mode:'automatic'` will only select non-spoiler, explicitly official-and-confirmed articles with `autoEligible===true`, `requiresReview===false` and `verification==='official'`; an invalid mode returns no candidates. Even a trusted source's `confirmed:true` cannot override speculative/rumor or spoiler wording detected in its headline. `includeSpoilers:true` admits spoiler stories for **manual review only**, never automation. The K-drama interpreter also refuses `storyKey` metadata from unverified ledgers. These are defence-in-depth content eligibility checks, **not** owner/admin/rights/queue authorization; C revalidates all those conditions before dispatch.

**K-drama interests/territories:** `chooseNews` also accepts `{genres:['Romance'],platforms:['Viki'],regions:['Nigeria']}` as optional preferences. Topic/show/genre/platform preferences are an OR match, whereas a selected region is a strict independent match against **verified official availability**. Both arrays and strings from malformed settings are handled without crashing, with bounded preference lengths. Unverified outlet claims cannot create a new platform, genre or streaming region assertion in a normalized candidate. The A/C user-facing UI and rights-protected saved settings must explicitly expose/authorize these fields before anyone claims this selection is live.

**Across-outlet news duplication:** The source-ledger `storyKey` is still preferred. For stories without an identical key, conservatively collapse headlines only when the same recognized show and event have strong shared meaningful tokens, were published within 72 hours, and do not disagree on numeric season/episode/year references. Prefer an official source over a review-only news outlet when both represent the same story. Different seasons and genuinely different announcements remain independently eligible. The rule is heuristic and must be inspected for borderline cases; it does not claim semantic news understanding.

**Safe previews:** `toReviewCard` only accepts bounded server-owned opaque paths under `/api/channel-media/` or `/api/channel-assets/` (or approved bounded image data). Query strings, encoded slash/dot sequences, external media hotlinks and path traversal are rejected. The source backend must also validate authentication, owner/JID, media bytes and active license rights; a syntactically safe URL is not a publishing grant.

**News RSS:** `rssNewsAdapter({id,name,url,official,fetchImpl,interpreter,now,maxAgeDays})`. Only configured HTTPS hosts are read; article links leaving the feed host are rejected by default. Supports bounded RSS and Atom common fields (including Atom `<category term="Drama"/>` metadata), CDATA, safe standard entities, XML DTD/ENTITY denial, a brief in-process TTL, immutable cached candidate arrays and **single-flight** coalescing so concurrent owners share one safe feed request, and source-specific interpretation. The feed cache stores only public source facts; owner/channel-specific interests and permissions are applied separately and never cached globally. A feed entry about a recognizable followed show, explicitly tagged `Drama` or `K-Drama` by the source, may be surfaced for **manual review** even without release/casting keywords; merely carrying a topic label cannot establish official fact, remove rumor flags, or permit automatic publication. This lightweight parser is not a full XML reader; prefer controlled feeds and expand coverage with deterministic tests before expanding sources. Fetching actual approved external feeds is an integration gate, not covered by fixture tests.

**Hard security boundary:** None of these source and ranking helpers knows an account, channel owner, connection proof, feature toggle in durable storage or publisher credentials. Agent C must enforce those on the server before curation/scheduling **and immediately before send**, with idempotency, revocation, disconnect, and per-channel isolation; Agent A must not expose this as a directly callable unauthenticated feed or post endpoint. Returning `autoEligible:true` does **not** imply account authorization or ownership.


**K-drama interpreter:** `interpretKDramaEntry(row,{showAliases,confirmedBySource})` in `kdrama.cjs` recognizes casting, releases, trailers, renewals, platforms, romance, speculative/rumor language and likely spoiler headlines. It extracts quoted or approved-show-list names, but *cannot* automatically verify claims. Official auto-eligibility requires a trusted, server-maintained `confirmedBySource[guid]` record on an official allowlisted source. `chooseNews(...,{includeSpoilers:false})` filters spoilers by default; owner can opt in. Event dates are stored separately from article publication dates. Heuristic tags and summaries must still be reviewed visually by A/E before live posting.


## Opt-in K-drama source profiles (NOT enabled or deployed)

`feeds.cjs` provides an inert, operator-approved registry for the publicly advertised **Soompi RSS** (`https://www.soompi.com/feed`) and **The Korea Times entertainment RSS** (`https://feed.koreatimes.co.kr/k/entertainment.xml`). The second feeds from `feed.koreatimes.co.kr` but links to exact allowlisted `(www.)koreatimes.co.kr` article hosts. Both publications are **independent news outlets, NOT official studios**; returned stories are **unverified, REVIEW FIRST** even when the headline uses words like “confirmed”. `createKDramaFeed(id,{operatorApproved:true,showAliases,fetchImpl})` requires explicit source/terms approval before any fetch. It drops entries without a recognized show and topical label, so unrelated K-pop feed items are not labelled K-drama. Original news is linked and attributed; only metadata-based original short recaps are candidates, never full article or copied copyrighted images. This is an integration starting point, not proof that upstream RSS permissions or live network responses were tested. Do not silently enable these profiles by default.

**Current media safety:** Candidate dimensions, byte estimates and likes are bounded and candidate nested provenance is frozen. Reader/publisher must still verify actual response MIME, file bytes, rights, owner/JID, channel status and message permission before enqueue and immediately before send. Both Reddit and news adapter requests are capped and fail closed on wrong hosts/unsafe formats. Reddit discovery additionally rejects off-subreddit permalinks, encoded/path-traversal variants and direct image links hosted outside Reddit's controlled `i.redd.it` / `preview.redd.it` still-image CDN; it does not grant media rights. Per-item malformed RSS metadata is isolated; an all-broken interpreter fails closed instead of falsely returning an empty successful feed. Newly selected news filters out stale posts even if a cached item was formerly fresh. Spoilers always require owner review even if a studio confirmed the original article; avoid spoilers by default.
